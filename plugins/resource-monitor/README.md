# 资源监控（Resource Monitor）

每 5 秒采样整机 CPU / 内存 / 网络，用**可缩放时间范围**（默认最近 10 分钟，最多 35 分钟）的趋势图展示占用最高的 **Top 10** 程序——
用来回答三个问题：**CPU 为什么莫名 100%**、**谁占了一大块内存**、**哪个程序在上传**。

## 功能

- **后台常驻采样**（5 秒一次），滚动保留最近 **35 分钟**；关掉界面也在采，重开即续上。
- 三个类别页签，每类都是「多线趋势图（默认近 10 分钟）+ 当前榜单」：
  - **CPU 占用**：按程序聚合，数值 = 占**整机** CPU 的百分比（与任务管理器口径一致，各程序相加 ≈ 100%）。
  - **内存占用**：程序所有进程的工作集之和。
  - **上传占用**：见下方「口径说明」。
- **按程序名聚合**：同名多进程（如多个 `chrome.exe`）合并为一条线，标注实例数（×N 进程）。
- **进圈 / 出圈滞回（可动态设置）**：默认「进 10 名上圈、掉到 15 名之外才移出」。
  界面顶部可改这两个数字并「应用」，立即生效（历史曲线同步重算）。
- **曲线不会无缘无故断线**（重要，见下节「曲线的连续性」）：
  - 程序**活着但这一拍占用为 0** → 不算掉出，线继续画到谷底（不断）；
  - 只有**排名真的跌出「出圈」值**，才移出跟踪，并把它的**历史旧段一并清掉**，
    以后再上榜从全新一段重新开始；
  - 进程**退出**后，宽限约 30 秒仍无数据才移出并清理（避免死程序平线堆积）。
- 顶部系统卡片：整机 CPU、内存（已用/总量 + 占比）、网卡**真实**上传/下载速率。
- **趋势图可缩放时间范围**：图表右上角三个图标 —— **放大（+）** 缩短时间跨度看细节、
  **缩小（−）** 拉长时间跨度、**回到最新（⟳）**。档位按 **5 分钟**一档：
  **默认最近 10 分**，放大到 **5 分**（最细），缩小每次 **+5 分**（10 → 15 → … → **35 分**，最粗）；
  X 轴刻度随跨度自动改写。放大后**按住图表拖动可平移**（看更早的时段），右上角标签显示当前范围。
- 图例（图下方的 tag 条）**点击即「只看这一个」**：点某个 tag → 图上只画该程序，tag 高亮；
  再点同一个 → 恢复全部；点另一个 → 直接切换。该选择按类别记住、随会话持久化。
  悬浮趋势图显示该时刻的程序数值；界面偏好（页签 / 单选）会记住。
- **单击图表定格某一时刻**：在趋势图上点一下，下方榜单（及顶部系统卡片）立即切到
  **那一刻**的采样快照（图上会画一条高亮竖线标出定格位置，榜单上方显示「定格榜单 · 时间」）；
  这样就能回看「一分钟前到底是谁在占 CPU」。
  - 清除定格：点提示条上的 **「取消定格」**，或**再点同一时刻**，或按 **Esc**，即刻恢复实时。
  - 放大后**按住拖动 = 平移**（看更早时段），**单击 = 定格**，两者不会互相干扰。
  - 定格只从**已收到的采样点**里选一拍，不额外请求后台；因此它天生就是「只显示当时的数据」。
- **导出 CSV**：一键导出当前保留窗口（最近 35 分钟）的三张表（Top 榜长表 / 系统级长表 / 趋势跟踪长表），
  UTF-8 带 BOM，Excel 直接打开不乱码（见下）。
- **打开文件位置**：榜单每行右侧「位置」按钮，在资源管理器中打开该程序的可执行文件
  所在目录并**选中该文件**（同名多实例取出现最多的那个安装位置）。
  - **点击即刻打开**：可执行路径在**每次采样时顺带取好并缓存**，点按钮直接用缓存路径，
    不再现场冷启动一次进程枚举（原先约 2s，现在约 0.2s）。程序刚启动、缓存还没有时，
    才回退到现场枚举一次。
  - **含空格的路径也能正确定位**（如 `C:\Program Files\...`）：传给资源管理器的参数形如
    `/select,"<完整路径>"`（引号**只包住路径**）。若像早先那样把 `/select,` 与路径整体交给
    系统加引号，资源管理器会认不出 `/select` 开关，**打开错误的位置**——这正是「有时打开
    的不是程序位置」的根因。
- **终止进程**：榜单每行右侧「终止」按钮，二次确认后按**程序名**结束其所有进程
  （含子进程树；监控自身相关进程——插件后台与采样 PowerShell——一律跳过；
  枚举后发现已自行退出的实例按「跳过」处理，不算失败）。
- 历史落盘到插件数据目录，进程重启后仍能看到；阈值也一并持久化。

## 进圈 / 出圈 是什么

榜单与趋势线用**滞回**控制可见范围，避免名次在边界抖动导致线闪烁：

| 概念 | 默认 | 含义 |
|---|---|---|
| **进圈** `enterN` | 10 | 排名 ≤ 该值 → 程序进入趋势图 |
| **出圈** `exitN` | 15 | 已在趋势图里的程序，只要排名仍 ≤ 该值就保留；跌出才移出 |

所以能读到「进 10 名上圈，掉到 15 名之后才下」的效果。两者都可在界面顶部改并「应用」
（出圈必须 ≥ 进圈）。“当前榜单”仍显示排名前 N（=进圈值）的程序。

## 曲线的连续性（为什么线会断）

一条趋势线**不应该无缘无故断开**。下面三种情况被区别对待：

| 情况 | 处理 |
|---|---|
| 程序**仍在运行**，只是这一拍占用为 0（空闲） | **不算掉出**：保留该程序，本拍值记 0 → 线继续压到谷底，**不断** |
| 程序**有占用**，但排名**跌出「出圈」值** | **真掉出**：移出跟踪，并**清掉它的历史旧段**；以后再上榜从新一段开始 |
| 进程**从系统里消失**（已退出） | 宽限约 30 秒（`TRACK_GRACE_TICKS` 拍×5s）后移出并清理旧段 |

因此你只会在这两种情形看到断口，且都符合预期：**采样本身出现空档**，或**某程序掉出后
重新上榜的新一段**。任何「一直没掉出 15 名」的程序，其曲线是整段连续的。

## 导出 CSV

点「导出 CSV」会把**当前保留窗口（最近 35 分钟）**导成 3 个文件（走浏览器下载，落到系统下载目录）：

| 文件 | 内容 | 列 |
|---|---|---|
| `resource-top-*.csv` | 每拍每类的 Top 榜长表 | `time,iso,category,program,value,instances` |
| `resource-system-*.csv` | 每拍的系统级指标 | `time,iso,cpu_pct,mem_used_bytes,mem_total_bytes,net_up_Bps,net_down_Bps` |
| `resource-trend-*.csv` | 每拍的趋势跟踪集合（未出圈的程序） | 同 Top 表 |

`category` 取值 `cpu` / `mem` / `up`；`value` 为原始数值（% / 字节 / 字节每秒），单位只在
列名体现，便于直接丢进 Excel 做透视。长表格式便于按 `program` 或 `category` 分组分析。


## 口径说明（重要，界面上也有标注）

**上传是近似值。** Windows 上免管理员**拿不到**「真·每进程发送字节」——那需要
管理员权限 + ETW（`Microsoft-Windows-Kernel-Network`）。本插件改用
`Win32_Process.OtherTransferCount` 的差值排名，它是一个「非文件 IO」计数：

- **包含**命名管道等非文件 IO，**且收发混合**，无法拆出「纯发送」；
- 因此它是一个**偏上界的近似排名**，适合回答「谁在上传」，但不是精确字节数。

顶部的「真实上传 / 真实下载」取自网卡累计字节（`Get-NetAdapterStatistics`），
是**系统级真实速率**，用来判断「上传榜的近似值是否与实际带宽相符」。

CPU 与内存是准确的（分别来自 `KernelModeTime + UserModeTime` 差值与 `WorkingSetSize`）。

## 平台

目前**仅支持 Windows**（依赖 `Get-CimInstance Win32_Process` 与 `Get-NetAdapterStatistics`）。
其它平台后台会正常完成握手，但界面会显示「本插件目前仅支持 Windows」。

## 后台方法（`ms.backend.call`）

| 方法 | 作用 |
|---|---|
| `init` / `capabilities` / `status` | 握手与能力/健康度 |
| `history` | 取回整段 35 分钟缓冲（含每点 `top` 榜与 `trk` 跟踪集合） |
| `setThresholds` | 设置 `{ enterN, exitN, topN }`，就地重算跟踪集合与历史曲线，并广播 `thresholds` |
| `clear` | 清空缓冲区（继续采样） |
| `exportCsv` | `{ kind: "top"\|"system"\|"tracked", minutes }` → `{ csv, filename, bytes }` |
| `listProcesses` | `{ name }` → 该程序名的所有进程实例（含可执行路径） |
| `killProcess` | `{ name, force }` → 结束该程序名所有进程（跳过监控自身与已退出实例），返回逐实例结果 |
| `revealProcessFile` | `{ name }` → 在资源管理器中选中该程序的可执行文件；失败以 `{ opened:false, reason }` 返回 |

通知：`tick`（每拍，带 `point` 与 `status`）、`status`、`cleared`、`thresholds`。

## 安全说明（终止进程 / 打开文件位置）

- 目标**程序名不拼进命令行**：它经环境变量 `MS_RM_NAME` 传给 PowerShell，命令行里永远
  不含用户输入，杜绝命令注入（进程名可能含空格 / 引号 / 中日文）。
- **枚举脚本显式输出 UTF-8**：否则中文机默认按 OEM 代码页（GBK）输出，Node 按 UTF-8
  解码后程序名（含中日文时）对不上，表现为「匹配 0 个」。
- **排除枚举自身**：列举那次 PowerShell 会被 `Get-CimInstance` 枚举到它自己，但它随即
  退出；若不排除，每次终止都会多出一个「已找不到该进程」的假失败（目标为
  `powershell.exe` 时尤其明显）。
- **绝不结束监控自身**：插件后台进程 pid 与长驻采样 PowerShell pid 一并列入受保护集合，
  命中即跳过并在结果里说明；否则终止 `powershell.exe` 会顺手弄断采样。
- 终止走 `taskkill /PID <n> /T /F`（带子进程树），逐实例返回成功/失败/跳过。
- **成败以「探活」为准，而非 taskkill 退出码**：同名父子进程被 `/T` 连带杀掉、目标在
  枚举后自行退出等正常情形下，taskkill 也会返回非 0。故杀前不存在 → 跳过，杀后消失 →
  成功，仍存活才算失败——判定与系统语言无关。
- **taskkill 输出按 OEM 代码页解码**：其错误走 stderr 且是 GBK（中文机 936），直接按
  UTF-8 会得到乱码；优先用 `gb18030` 还原，失败原因才可读。
- 打开文件位置的可执行路径来自系统枚举（非用户输入），以独立参数交给
  `explorer /select,"<path>"`（**引号只包路径**，且用 `windowsVerbatimArguments` 原样传递，
  不拼进 shell）；含空格路径因此也能正确定位。受保护进程（如 `svchost.exe`）拿不到
  路径时返回可读原因，而不是报错。


## 可调项

- 采样间隔：环境变量 `MS_RM_INTERVAL_MS`（毫秒，默认 5000）。
- 进圈 / 出圈：界面顶部动态设置（随历史持久化）。
- 保留窗口 / 默认 TopN：`backend/aggregate.mjs` 顶部的常量（`WINDOW_MS` / `TOP_N` / `ENTER_N` / `EXIT_N`）。
