# Windows 桌面快捷方式角标：参照数据与复刻说明

本目录下 `#matchResult .plugin-badge`（插件项左下角角标）的造型，是照着
**Windows 桌面快捷方式图标**复刻的。参数不是估计值，是把真实 `.lnk` 交给
shell 渲染后逐像素量出来的。

## 怎么复现这份参照

参照脚本是一次性的（取完数据就删了）——这里记录方法，需要复核时按步骤重做即可。

取「Windows 原版角标」的渲染结果：

1. 建一个真实 `.lnk`（`WScript.Shell` 的 `CreateShortcut`），把 `IconLocation`
   指向一个**自己写的纯深色 `.ico`**。用纯色是关键：底板后面是不是透的、
   描边什么颜色，只有在高对比底上才量得准。
   - `.ico` 建议手写字节（32bpp BGRA + AND 掩码），因为 System.Drawing 存 ICO
     容易丢 alpha；32×32 的数据段布局：`BITMAPINFOHEADER`（高写两倍）+ 像素自下而上 + 掩码全 0。
2. 用 `SHGetFileInfo(lnk, 0, ref fi, size, SHGFI_ICON | SHGFI_LINKOVERLAY)`
   取句柄——这是资源管理器画桌面图标走的同一条路，比猜注册表里 overlay 资源 id 可靠。
   - 顺带取一份**不带** `SHGFI_LINKOVERLAY` 的，用来分离出「角标」的贡献。
3. 句柄转 `Bitmap` 存 PNG，然后逐像素读：
   - 找 `alpha>250 && rgb>235` 的连续区域 = 底板外接框
   - 印出底板区域的 alpha 图与颜色图，就能看出边框色渐变、圆角、箭头核心色

读像素用 Node 手写 PNG 解码即可（`zlib.inflateSync` + 反滤波），
本仓库没有引入图形库的依赖，不值得为一次性核对加一个。

量到的结论见上面两张表；`test/plugin-ui.test.mjs` 里的角标断言就是把这些
数字固化成了回归检查，日常改样式跑测试就够，不必再动 Windows API。

## 量出来的参数（32×32 图标）

| 项目 | 实测值 | 换算到本项目的 24px 图标 |
|---|---|---|
| 底板尺寸 | 13×13 px（40.6%） | **10px** |
| 底板位置 | 距图标左下角各 1px | 2.5px（见下方「为什么不是 1px」） |
| 底板底色 | `#ffffff`，**alpha=255 不透明** | 同左 |
| 底板描边 | 顶边 `#e5e9ef` → 底边 `#c8d0de`，约 1px，越往下越深 | `1px solid #c8d0de` |
| 底板圆角 | ≈2px | `2px` |
| 图形颜色 | 最饱和处 `#0a85d9`（蓝） | 同左 |
| 图形占比 | 约 7/13 底板宽 | `7px` |

### 底板是「不透明」而非「半透明」

这点专门验过：把 `.lnk` 的图标换成纯深蓝 `#1b2a4a`，角标底板区域取样仍是
`rgb(255,255,255) alpha=255`。如果是半透明白蒙版，这里必然会泛出深蓝。
所以 CSS 用实色 `background: #fff` 即可，不需要 `rgba()`。

（为此专门写了「纯色 ico + 指定 IconLocation」那一步，原因见上一节第 1 条。）

### 为什么偏移取 2.5px 而不是 Windows 的 1px

Windows 贴在 1px 是因为桌面图标是**方形**的。本列表的 favicon 有圆角
（`#matchResult img` 的 `border-radius: 30%`，24px 图标即 7.2px 半径），
底板贴死 0 会被圆角切掉一个角。

左下角的裁切区判定为 `{ x < 7.2 且 y > 16.8 且 距(7.2,16.8) > 7.2 }`，
代入底板最外侧那个角 `(d, 24-d)`：

| d | 该角到弧心 | 结果 |
|---|---|---|
| 1px（Windows 原值） | 8.77 | 出界，会被切 |
| 2px | 7.35 | 出界 |
| 2.109px | 7.20 | 临界 |
| **2.5px（采用）** | **6.65** | **在内，留有余量** |

注意这个约束**只跟 d 有关、与底板尺寸无关**（最外侧角恒为 `(d, 24-d)`），
所以以后调底板大小不必重算偏移。

## 回归锚点

`test/plugin-ui.test.mjs` 里有一组针对角标的断言，量的是计算样式与
`getBoundingClientRect()`，涵盖：左下角定位、不越出 favicon、不被圆角切角、
白底 + 1px 描边 + 2px 圆角、尺寸比例 35%~50%、图形为 `rgb(10,133,217)`。

其中有一条值得单独说：**图形颜色必须写在 `svg path` 上，不能只写 `svg`**。
因为图形自带 `fill="#999999"` 这个**表示属性**，而 SVG 表示属性与 CSS 的
优先级关系是「CSS 规则直接命中该元素」才生效；写在父级 `svg` 上只是**继承值**，
指定值恒定压过继承值，灰色照旧渲染。这个坑实际踩过一次（截图才发现）。
